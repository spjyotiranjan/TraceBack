## Reference differences that are intentional

- Shared nav/dock, footer and background follow the approved overrides, not the PDF shell. The mobile dock must not prevent a recovery action from being reached.
- Expanded `8705`/`10357` show **Hide filters** beside the report action, before search. The app keeps the same disclosure next to the fields in the form: search → toggle → Type, with Escape and focus return. Do not visually reorder the focused toggle away from its keyboard sequence. At narrow reflow widths buttons can stack.
- In applied/empty-match/retry phone frames `8873`, `10533`, `8966`, `10634`, `9194`, `10886`, the query chip can appear next to Type even though it is last on desktop. The app uses one wrapping DOM/tab order rather than moving an interactive chip ahead of its keyboard position.
- Empty Later `8250`/`9870`/`9121`/`10805` show **Previous page** and pager chrome. Production offers **Back to page 1** with the filters intact, since an arbitrary later page and its predecessor can both be empty. No Active `8170`/`9782`/`9055`/`10731` keeps the existing report action; Retry keeps the original request including its page and original encoding. Card dates keep the explicit **Reported** label (not the date the item was lost/found). Default frames show **Next** with six sample rows; the app does not advertise a next page unless the server establishes one. Last Page uses a disabled **Next** indicator, not a link.

## After capture

- At 1440 px the intro and grid align at x=120, the toolbar is 1200 × 186 px, and the three-column grid starts at y=502. At 390 px they align at x=20, the collapsed toolbar is 350 × 154 px, and the single-column grid starts at y=482. The search and report actions measure 48 px high at both widths; the media area is 212 px in both themes. Card photo sampling can differ from the PDF square cut-outs: production uses the uploaded photo crop, not the prototype content.
- The 34 captured states show the unframed intro, compact controls, corrected card/badge styling, contextual recovery and outlined paging. Recovery-panel text can wrap differently from the prototype. The approved shell means the amount of card and panel content visible above the dock is not pixel-identical.
- Chromium also exercised 896→895 px focus transfer, 320 px reflow, native 200% page zoom, keyboard, emulated touch, no-JavaScript GET, reduced motion and the shared fixed-background motion suite. The Browse browser journeys cover count and availability with a 24-item page and one-item last page, filter URL preservation, page reset and same-query 503 retry. The MongoDB test filters a disposable loopback data set, and the layout test visits the six real Razor detail routes for the fixture IDs. No physical phone or live storage was used.
- Browse requires sign-in; access was not changed to create a guest version. There is no separate Browse pending/skeleton frame. The request remains a server-rendered GET rather than adding a new transient client state.
