## Intentional differences and limits

- **Overview `37211`, `37803`, `38389`, `39029` and the report/claim component sheets:** Keep the underline as a visible link affordance on actual Details links and keep the **Reported** date label so it cannot be mistaken for the lost/found date. The existing page opens a report again through its Details URL; it has no action that changes a resolved report back to Active. No management routes or authorization rules were added.
- **Approved long row (`37265` / `37857`, component `37174` / `37766`):** The desktop sample is 106px despite its title fitting on one line. The phone sample is 161px with a three-line title. The runtime sample is 82/157px (one/three lines); longer records expand to fit their actual text. The app does not insert line breaks or extra height for a specific sample or status. Below-fold mobile cards/claims and the final desktop rows are partly or wholly outside the PDF viewport; their layout was compared using the component sheet and saved frame geometry, with full-page and scrolled app checks rather than a claim of visible page-pixel equivalence.
- **Submitted `37568`, `38156`, `38778`, `39414`:** The notice keeps production copy and the row displays its real submission date, not the mock's fixed date. Actual photos still use the shared crop and fallbacks; sample photos were used only in browser comparisons.
- **No dedicated PDF page-1 pending, generic service-error or permission-denied Dashboard frame.** Dashboard remains an authenticated server-rendered GET with the existing error fallback; no synthetic skeleton or new retry action was added. Guest denial, absent records/images and one-time success feedback were exercised. A Dashboard-specific datastore outage, physical phone and production storage were not exercised.

For local recapture, run the Dashboard browser test with the repository's Playwright and disposable Mongo configuration (`TRACEBACK_BROWSER_TESTS=1`, `TRACEBACK_TEST_MONGO_URI`). Set `TRACEBACK_DASHBOARD_EVIDENCE` to a local output directory for viewport/full-page screenshots and geometry. `DASHBOARD_REFERENCE_PHOTOS` can point at local PNG samples named `<bottle|headphones|keys>-<1440|390>-<light|dark>.png`; the normal test uses local image responses without the design photos. `DASHBOARD_CAPTURE_BASELINE=1` is only for the unchanged baseline and skips the new geometry checks, not the real workflows.
